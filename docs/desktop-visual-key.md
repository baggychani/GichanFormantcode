# Desktop Visual Key

이 문서는 Tauri/React 메인 창의 실제 화면을 디자인 기준점으로 고정한다. 기존
PySide `main.py`에는 적용하지 않으며, 마이그레이션 UI 진입점인 `desktop_main.py`에서
사용한다. 새 화면은 임의로 새 테마를 만들지 않고 이 기준을 따른다.

## 1. 제품 인상

GichanFormant는 어두운 개발자 도구나 과장된 대시보드가 아니라, **밝고 정돈된
음성 분석 작업공간**으로 보인다. 넓은 푸른 회색 작업면 위에 백색 패널을 올리고,
청록은 연결·주요 실행·측정 신호에만 제한적으로 쓴다.

| 가치 | 화면 원칙 |
| --- | --- |
| 명료한 위계 | 제목, 현재 분석, 다음 행동의 순서가 즉시 읽혀야 한다. |
| 분석 도구의 정확성 | 수치와 설정은 조밀하지만 답답하지 않게 보인다. |
| 조용한 깊이 | 테두리·미세한 그림자·옅은 격자로 깊이를 만들고 강한 glow는 피한다. |
| 시각적 근거 | 비어 있는 상태에서도 옅은 포먼트 궤적과 점으로 분석 도구의 성격을 보여 준다. |
| 점진적 제어 | 자주 쓰는 설정은 전면에, 드문 설정은 우측 사이드바 또는 접힌 영역에 둔다. |

피해야 할 것:

- 딥 차콜을 기본 테마로 삼는 분석실/터미널 느낌
- 같은 무게의 버튼을 여러 개 배치하는 것
- 과도한 유리 효과, glow, 무거운 그림자
- 비어 있는 화면을 로그나 진단 UI로 채우는 것

## 2. 색·표면 기준

> **Light analysis workspace + teal instrument signal + restrained blue-violet spectral color**

- 라이트 테마에서는 현재 메인 창처럼 작업면은 푸른 회색, 카드·입력면은 백색,
  본문은 진한 남청, 보조 정보는 슬레이트 회색을 사용한다.
- 청록은 primary action, 온라인 상태, 선택된 핵심 제어에만 쓴다.
- 파랑·보라색은 포먼트 유형과 시각화 보조색이다. 오류와 경고는 별도 색으로 유지한다.
- 첫 실행 테마는 시스템 설정을 따른다. 사용자가 테마를 직접 바꾼 경우에만 그 선택을
  저장해 우선 적용한다. 다크 테마도 라이트 메인 화면의 정보 위계와 간격을 그대로
  유지하는 동등한 모드다.
- 브랜드 아이콘과 창 아이콘은 기존 `assets/icon.ico`를 사용한다. Tauri 기본 아이콘으로
  대체하지 않는다.

색상·배경을 새로 만들기 전에 `desktop/src/styles/tokens.css`의 semantic token을 추가하거나
기존 token을 사용한다.

## 3. 정보 구조

```text
Header       제품 정체성 / 현재 작업 경로 / 테마·가이드
Source rail  데이터 추가 / 파일 목록 / 프로젝트 동작
Workspace    분석 안내 / 현재 분석 / 미리보기 / 다음 행동
Settings     분석 유형 / 축·처리 옵션
Status line  연결 상태와 현재 작업 상태
Toast        실패·주의가 필요한 경우에만 짧게 표시
```

시각적 무게는 `Workspace overview > analysis flow + preview > side rails > chrome`
순서다. 미리보기는 결과를 빠르게 확인하는 증거이지 화면 전체를 지배하는 모니터가 아니다.

## 4. 컴포넌트 원칙

- 헤더의 primary action은 한 화면에 하나만 둔다.
- 파일 추가는 버튼보다 drag-and-drop 가능한 입력 영역처럼 보여야 한다.
- 플롯 유형은 이름, 수식, 간결한 설명이 함께 보이는 선택 항목으로 표현한다.
- 분석 설정은 번호가 붙은 짧은 섹션으로 나누고, 드문 설정은 우측 레일에 둔다.
- 빈 상태에는 다음 행동과 함께 옅은 분석 시각 요소를 제공한다.
- 오류는 일시 toast로 알리고, 지속 상태는 하단 status line에만 남긴다.

## 5. 타이포그래피와 간격

- UI sans: `Pretendard`, `Noto Sans KR`, `Malgun Gothic`, `Segoe UI` 순서.
- 수치와 상태: `Cascadia Code` 또는 `Cascadia Mono`.
- 설정 이름과 설명은 11px 미만으로 낮추지 않는다. 섹션 제목은 최소 13px이다.
- 한글에는 과도한 자간을 적용하지 않는다.
- 좌우 레일은 고정 폭, 중앙 작업 영역은 유동 폭으로 둔다.
- 카드 반경은 8–16px, 테두리는 낮은 대비, 그림자는 흰 패널을 작업면에서만 분리할 정도로
  제한한다.

## 6. 상태와 모션

- 상태는 색만으로 표현하지 않고 아이콘과 텍스트를 함께 쓴다.
- hover와 패널 전환은 180ms의 opacity/transform/border 변화로 제한한다.
- 처리 중에는 레이아웃을 바꾸지 말고 상단 progress line 또는 버튼 상태를 사용한다.
- `prefers-reduced-motion`에서는 모션을 제거한다.
- 로드 전 빈 상태도 최종 화면과 같은 레이아웃 크기를 유지한다.

## 7. 다음 화면: 단일 대화형 플롯

단일 플롯은 이 메인 창의 연장선으로 구성한다.

```text
Left sidebar    데이터·레이어·가시성
Center stage    플롯 캔버스와 플롯 전용 도구
Right sidebar   분석 / 디자인 / 내보내기
Status line     현재 도구·선택·저장 상태
```

비교 모드는 이 단계의 범위에 넣지 않는다. 단일 플롯의 기능 동등성을 먼저 확보하고,
기존 PySide `PlotPopup`은 계속 유지한다. 장차 비교 모드를 추가할 때는 양쪽 패널을
복제하지 않고 우측 디자인 영역 안의 `A | B` 세그먼트로 확장한다.

## 8. 검증 질문

1. 첫 시선이 현재 분석과 다음 행동으로 향하는가?
2. 현재 메인 창의 밝은 작업면·백색 패널·청록 신호 체계가 유지되는가?
3. 빈 상태가 완성된 분석 도구처럼 보이는가?
4. 설정 용어가 분석 작업에 익숙한 사용자가 바로 이해할 수 있는가?
5. 오류와 로그가 작업 공간을 침범하지 않는가?
6. 새 React 화면이 기존 PySide 진입점이나 창을 제거하지 않았는가?
